# Архитектурное решение по логированию

## Мотивация

### Почему нужно логирование
Текущие проблемы разбираются на основе жалоб клиентов, что занимает много времени и ресурсов поддержки. Логирование позволит системно отслеживать события, быстро выявлять причины задержек и ошибок, снижая нагрузку на команду и улучшая качество обслуживания.

### Что даст компании
- Ускорение разбора инцидентов: Вместо опросов клиентов — анализ логов.
- Проактивное обнаружение проблем: Мониторинг аномалий.
- Улучшение производительности: Оптимизация на основе данных о загрузке.

### Метрики
Технические:
- Время на разрешение инцидента: Снижение с дней до часов.
- Количество ошибок в логах: Мониторинг роста.
- Производительность API: Время ответа, количество таймаутов.

Бизнес:
- Количество жалоб клиентов: Снижение на 50%.
- Время выполнения заказов: Соблюдение дедлайнов.
- Уровень удовлетворенности клиентов: Рост за счет быстрого реагирования.

## Анализ системы и планирование логирования

### Необходимые логи
Логи должны собираться из всех трех приложений (бэкенд-части), а также из RabbitMQ для отслеживания сообщений.

Список логов уровня INFO:
- Изменение статуса заказа: Время, идентификатор пользователя, номер заказа, предыдущий и новый статус.
- Создание заказа: Время, пользователь, детали заказа (тип, файл/конструктор).
- Расчет стоимости: Время начала и окончания, номер заказа, результат (успех/ошибка), время выполнения.
- API вызовы: Время, endpoint, параметры, ответ, пользователь (для внешних API).
- Входы/выходы пользователей: Время, пользователь, система.
- Операции в MES: Взятие заказа в работу, завершение этапов (MANUFACTURING_STARTED, COMPLETED и т.д.).
- Сообщения в RabbitMQ: Отправка/получение сообщений между CRM и MES.

### Уровни логирования
- **INFO**: Для основных событий, как указано выше.
- **WARN**: Для потенциальных проблем, например, задержки в расчетах (>5 мин), неудачные попытки подключения к RabbitMQ.
- **ERROR**: Для исключений, сбоев в API, ошибок базы данных.
- **DEBUG**: Для детальной отладки во время разработки, отключено в продакшене.

## Приоритет систем для логирования и трейсинга
В первую очередь — MES, так как там основные проблемы с производительностью дашборда и статусами заказов. Затем CRM для отслеживания интеграции. Онлайн-магазин — последним, так как проблемы там менее критичны. Трейсинг добавить параллельно для end-to-end отслеживания заказов.

## Предлагаемое решение

### Реализация
Использовать стек ELK (Elasticsearch, Logstash, Kibana):
- **Filebeat**: Сбор логов с EC2 инстансов приложений.
- **Logstash**: Обработка и отправка в Elasticsearch.
- **Elasticsearch**: Хранение и индексация.
- **Kibana**: Визуализация и дашборды.

Компоненты:
- Добавить агентов Filebeat на каждый EC2.
- Настроить Logstash для парсинга логов.
- Интегрировать с приложениями: В Java (Spring Boot) использовать Logback, в C# — Serilog.

### Политика безопасности
- Шифрование логов в транзите (TLS).
- Маскировка чувствительных данных (PII, как email, адреса) в Logstash.
- Доступ к логам: Только разработчики, DevOps, продакт-менеджер по ролям в Kibana. Администраторы — полный доступ.

### Политика хранения
- Отдельные индексы по системам (mes-logs, crm-logs, shop-logs).
- Хранение: 30 дней для INFO/WARN, 90 дней для ERROR.
- Размер: Ротация индексов, ограничение на 100GB на индекс.

### Система анализа
- Алёртинг: Настроить в Kibana/Elasticsearch Watcher для ошибок, задержек >10 мин, роста заказов.
- Поиск аномалий: Использовать машинное обучение в Elasticsearch для обнаружения DDoS (внезапный рост заказов) или сбоев.

## Дополнительное задание: Критерии выбора технологии

| Лицензия         | Elastic License (бесплатно для базового) | Apache 2.0 (открытый) | Проприетарная (платная) | Apache 2.0 |
| Масштабируемость | Высокая, кластеры | Высокая | Высокая | Средняя |
| Интеграция с Yandex Cloud | Хорошая, managed ES | Хорошая | Ограниченная | С Prometheus |
| Стоимость        | Низкая (самоуправляемый) | Низкая | Высокая | Низкая |
| Функциональность | Богатая (поиск, визуализация) | Аналог ELK | Корпоративная | Простая, для логов |

Выбор: ELK, так как бесплатный, мощный, подходит для компании.
